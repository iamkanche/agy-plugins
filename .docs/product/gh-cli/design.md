# GitHub CLI Workflows Design

## 1. Subagent Delegation
GitHub actions delegate execution to `@gh-operator` (`plugins/kanche/agents/gh-operator/agent.json`), ensuring:
- Safe GitHub CLI execution via `gh pr create`, `gh pr review`, `gh pr merge`.
- Structural Conventional Commit title/body parsing.

## 2. Universal Destructive Gating
Every remote-mutating action (`git push` in PR creation, `gh pr merge`) unconditionally prompts the user for confirmation using the interactive `default_api:ask_question` tool. Skills stand alone without mode-conditional bypasses.

## 3. PR Review Output Format & Atomic Submission Design
PR review output bodies generated by `/kanche:gh-cli-pr-review` strictly follow the standardized layout:
- `#  Summary`: Short summary bullets, overall severity rating (e.g. `6/10`), total files, and total lines of code reviewed.
- `## Review Summary`: ASCII table categorizing findings across `🔴 HIGH`, `🟡 MEDIUM`, and `🟢 LOW` severities.
- `---` separator followed by inline code comments.
- **JSON Payload Architecture (`review.json`)**: When `--json` is enabled or in automated pipelines, reviews are formatted into a GitHub REST API payload (`{ "body": "...", "event": "COMMENT", "comments": [...] }`) and submitted atomically in a single request via `gh api --method POST /repos/{owner}/{repo}/pulls/{pull_number}/reviews --input review.json`.
