# Product Memory

<!-- durable cross-feature memory; written by /kanche:sdd-sync -->

- **Zero Autonomous Destructive Execution**: Every destructive or remote-mutating operation (`git push`, `git commit`, `rm`, `rm -rf`, branch/tag deletions, `git stash drop`, and `gh pr merge`) MUST gate on interactive human confirmation via the `default_api:ask_question` tool unconditionally across all execution modes. (Grounded in `plugins/kanche/rules/destructive-safety.md`.)
- **Skills Stand Alone Principle**: Individual skills are completely decoupled and self-contained. Skills do NOT contain auto-mode bypass logic, caller-mode checks, or mode-conditional skips. Every skill is 100% safe and independent when executed standalone.
- **Autonomous Software Engineering Team (16 Subagents)**: The plugin packages 16 specialized, domain-focused subagents (`researcher`, `scrum-master`, `analyst`, `architect`, `designer`, `planner`, `coder`, `frontend-expert`, `backend-expert`, `reviewer`, `validator`, `tester`, `security-engineer`, `devops`, `git-operator`, `gh-operator`) in `plugins/kanche/agents/`, all unified on `model: flash` (Gemini Flash High) with zero SDD couplings.
- **Universal Review Interface (`review-verdict`)**: All review skills (`code-review`, `qa-review`, `design-review`, `design-specs-review`, `planner-review`) emit structured `review-verdict` fenced blocks, consumed in closed-loop evaluation cycles by generator skills (`code-implement`, `design-init`, `design-specs`, `planner-tasks`). The legacy `sdd-review` moniker is completely deprecated.
- **Enhanced GitHub PR Review Workflow**: `/kanche:gh-cli-pr-review` supports `--json` / `--format=json` export to `review.json` and posts structured reviews (`#  Summary`, `## Review Summary`, ASCII severity tables, and inline code comments) in a single atomic request via `gh api`.
- **Safety Invariants**: Safety rules (no force-push, no `--no-verify`, protected-branch refusal, secrets detection, self-approval prohibition) are enforced unconditionally across all skills and workflows.
- **Gated Operations via Workflows**: Commits, pushes, and PR operations MUST be performed using formal plugin slash commands (e.g. `/kanche:git-commit`, `/kanche:git-push`, `/kanche:gh-cli-pr-create`, `/kanche:gh-cli-pr-merge`, `/kanche:sdd-run`) instead of raw shell commands.
- **Flattened Plugin Skill Structure**: All 40 skills in the `kanche` plugin use single-level flattened subdirectories under `plugins/kanche/skills/<skill-name>/SKILL.md` (e.g. `sdd-init`, `git-commit`, `gh-cli-pr-create`, `code-review`, `security-scan`) to ensure full compatibility with the `agy plugin install` CLI engine and AGY slash command discovery.
- **QA & E2E Validation via MCP**: QA validation and code review workflows (`/kanche:qa-validate`, `/kanche:qa-review`) leverage Playwright MCP tools (`browser_navigate`, `browser_screenshot`, `browser_console`) for visual testing and E2E browser automation.
- **Mandatory Pre-Execution Skill Inspection**: ALWAYS inspect `plugins/kanche/skills/<skill-name>/SKILL.md` using `view_file` immediately before executing any skill or workflow step. Verify all default flags, inputs, CLI options, and step sequence strictly against the skill file. Never assume or override default flags.
