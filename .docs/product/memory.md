# Product Memory

<!-- durable cross-feature memory; written by /kanche:sdd-sync -->

- **Zero Autonomous Destructive Execution**: Every destructive or remote-mutating operation (`git push`, `git commit`, `rm`, `rm -rf`, branch/tag deletions, `git stash drop`, and `gh pr merge`) MUST gate on interactive human confirmation via the `default_api:ask_question` tool unconditionally across all execution modes, and is enforced at runtime via `plugins/kanche/hooks.json` (`hooks/destructive_gate.py`, `hooks/secret_guard.py`). (Grounded in `plugins/kanche/rules/destructive-safety.md`.)
- **Skills Stand Alone Principle**: Individual skills are completely decoupled and self-contained. Skills do NOT contain auto-mode bypass logic, caller-mode checks, or mode-conditional skips. Every skill is 100% safe and independent when executed standalone.
- **Autonomous Software Engineering Team (19 Subagents)**: The plugin packages 19 specialized, domain-focused native Markdown subagents (`researcher`, `scrum-master`, `analyst`, `architect`, `data-architect`, `designer`, `planner`, `coder`, `frontend-expert`, `backend-expert`, `debugger`, `reviewer`, `validator`, `tester`, `security-engineer`, `token-optimizer`, `devops`, `git-operator`, `gh-operator`) in `plugins/kanche/agents/*.md`, invoked with `model: flash` (Gemini Flash High).
- **Universal Review Interface (`review-verdict`)**: All review skills (`code-review`, `qa-review`, `design-review`, `design-specs-review`, `planner-review`) emit structured `review-verdict` fenced blocks, consumed in closed-loop evaluation cycles by generator skills (`code-implement`, `design-init`, `design-specs`, `planner-tasks`). The legacy `sdd-review` moniker is completely deprecated.
- **Enhanced GitHub PR Review Workflow**: `/kanche:gh-cli-pr-review` supports `--json` / `--format=json` export to `review.json` (staging temporary payloads in `/tmp` by default) and posts structured reviews (`#  Summary`, `## Review Summary`, ASCII severity tables, and inline code comments) in a single atomic request via `gh api`.
- **Safety Invariants**: Safety rules (no force-push, no `--no-verify`, protected-branch refusal, secrets detection, self-approval prohibition) are enforced unconditionally across all skills, workflows, and `hooks.json`.
- **Gated Operations via Workflows**: Commits, pushes, and PR operations MUST be performed using formal plugin slash commands (e.g. `/kanche:git-commit`, `/kanche:git-push`, `/kanche:gh-cli-pr-create`, `/kanche:gh-cli-pr-merge`, `/kanche:graph-run`) instead of raw shell commands.
- **Flattened Plugin Skill Structure**: All 56 skills in the `kanche` plugin use single-level flattened subdirectories under `plugins/kanche/skills/<skill-name>/SKILL.md` to ensure full compatibility with the Antigravity plugin engine and `/kanche:<skill-name>` discovery.
- **Executable Graph Health & Plugin Validation**: `/kanche:qa-validate` runs `scripts/graph_health.py` (native AST, JSON, relative import, circular dependency, and `graphify` checks) and `/kanche:plugin-validate` runs `scripts/validate_plugin.py`, plus Playwright/Chrome DevTools MCP for visual E2E testing.
- **Mandatory Pre-Execution Skill Inspection**: ALWAYS inspect `plugins/kanche/skills/<skill-name>/SKILL.md` using `view_file` immediately before executing any skill or workflow step. Verify all default flags, inputs, CLI options, and step sequence strictly against the skill file. Never assume or override default flags.
